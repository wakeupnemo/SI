# SIQuester Cross-Platform v0.2 question authoring

This document is the implementation boundary for v0.2.0. It records the
canonical behavior found in `test/SIGame/SIGame.Tests/SIGameTestNew.siq` and
the smallest authoring extension needed to reproduce it from a new package.

## Demo behavior matrix

The fixture contains 35 questions. Questions that differ only in literal text,
media bytes, or price are grouped below. The fixture contains no explicit
`<script>` elements: these behaviors use the canonical legacy question type,
question parameters, ordered question content, and optional `answer` content.

| Authoring behavior | Canonical type | Material parameters and price behavior | Question/answer flow |
|---|---|---|---|
| Round default | empty | Ordinary price; the player resolves empty type to `simple` in normal rounds and `stakeAll` in final rounds | Uses the round's default script without writing an explicit type |
| Simple question | `simple` | No type-specific parameters | Ordered question content, answer acceptance, optional post-answer content |
| Stake | `stake` | Question price remains the board price; the game selects the highest visible stake | Ordered content, direct answer, optional post-answer content |
| All-in stake | `stakeAll` | All possible stakes are offered and hidden from opponents | Ordered content, direct answer, optional post-answer content |
| Secret, fixed price | `secret` | `theme`; `price=numberSet(fixed)`; recipient normally excludes current player | Select recipient, announce theme and price, show question, accept answer |
| Secret, round minimum/maximum | `secret` | `price=numberSet(0,0,0)` is the canonical round-min/max sentinel | Same secret flow; game derives the two prices from the round |
| Secret, stepped range | `secret` | `price=numberSet(min,max,step)`; demo also allows any recipient | Same secret flow with selectable stepped prices |
| Secret, public price | `secretPublicPrice` | `theme`; endpoint `numberSet`; recipient excludes current player | Theme and price are announced before recipient selection |
| Secret without question | `secretNoQuestion` | Fixed `numberSet`; recipient excludes current player; no question content is required | Recipient/price selection then immediate acceptance; no question/answer stage |
| No-risk / for yourself | `noRisk` | Uses current player and the canonical price multiplier behavior | Ordered content, direct answer, optional post-answer content |
| For everyone | `forAll` | No additional parameter | All players answer the same ordered content |
| Custom/manual | `custom` | No canonical library script in the demo | Preserved and authorable as an explicitly manual question; no invented behavior |
| Empty structural cell | empty | `Question.InvalidPrice` (`-1`) and empty content/answer | Preserves the demo's disabled/empty table position |

Unknown future type names and parameters are not normalized. They remain
visible as an unknown behavior and survive ordinary open/save unless the author
explicitly chooses a known behavior.

### Answer and timing variants

| Variant | Canonical representation | Demo shape |
|---|---|---|
| Text | `right` and `wrong` answer collections | One or several right answers and optional wrong answers |
| Select | `answerType=select`, `answerOptions` content group | Four textual options; right answer stores the selected option text |
| Number | `answerType=number`, `answerDeviation` | Numeric right answer with deviation `5` (HTML demo uses deviation `0`) |
| Point | `answerType=point`, `answerDeviation` | Question image plus invariant `x,y,aspect` right answer and deviation `0.05` |
| Client-managed | `answerType=client` | Used by the HTML minigame; no ordinary text answer is required |
| Limited answer time | `answerDuration` | Fifteen-second answer window |

### Ordered content variants

The existing canonical content list must support these distinct order and
timing shapes without raw script editing:

| Stage | Demo-supported shapes |
|---|---|
| Question | text; replic then timed screen text; image then replic; background audio; screen video; non-waiting text then audio; non-waiting image then audio; multiple images with only the final item waiting; image then screen text; screen text then image; inert packaged HTML followed by text; text followed by timed HTML |
| Post-answer | image; background audio; video |
| Item controls | placement, duration, wait-for-finish, media reference, and stable list order |

Application-owned preview policy remains authoritative: this milestone makes
the demo's packaged HTML reference authorable and preservable but does not add
general HTML execution or a new rendering backend.

## UX and implementation plan

1. Add one localized high-level behavior selector to the typed question
   inspector. It offers round default, simple, stake, all-in, the three secret
   forms, no-risk, for-everyone, and custom/manual. An opened unknown value is
   shown explicitly and is not changed merely by displaying the inspector.
2. Show a contextual Secret settings card only for secret-family questions.
   It edits the canonical theme, recipient rule, and `NumberSet` through friendly
   modes: fixed value, round minimum/maximum, two endpoints, and stepped range.
3. Reuse the existing ordered `ContentItemsEditor` for a normal Post-answer
   content section. Creation/removal uses the retained `AddComplexAnswer` and
   `RemoveComplexAnswer` commands, so image/audio/video bytes, dirty tracking,
   undo, and safe-save ownership stay on the current paths.
4. Expose the retained `answerDuration` through a small optional typed control.
   Treat it as orthogonal to question behavior and preserve it when the author
   explicitly switches behavior.
5. Keep the lower-level explicit-script editor available for packages that
   already contain scripts, but do not require it for any demo-supported normal
   behavior. Do not synthesize scripts or create another question model.
6. Add focused ViewModel round-trip acceptance tests that create questions from
   a new package through the same commands/properties as the UI, save through
   the existing safe persistence path, reload with `SIDocument.Load`, and compare
   type, parameters, ordered content, answers, and media bytes. Add headless UI
   coverage for selector/contextual visibility and post-answer authoring.

## Matrix sanity check

The selector covers every distinct demo type, including empty round-default and
manual `custom`. Secret controls cover all four `NumberSet` shapes and both
recipient modes. Existing answer editors cover every answer mode; adding answer
duration closes the remaining timing gap. Existing ordered question-content
editing covers every question-stage media/order combination; the reused
post-answer editor closes the image/audio/video-after-answer gap. No demo
behavior requires an explicit script or a second serialization path.

## Completion evidence

All matrix rows are implemented and verified for v0.2.0.

- `DemoBehaviors_CreatedFromNewPackageCommands_SaveAndReloadCanonicalSemantics`
  starts with `SIDocument.Create`, uses the retained hierarchy/question command
  paths, safely saves, reloads with `SIDocument.Load`, and compares every
  distinct type/parameter shape, answer mode, ordered content shape, post-answer
  content, normal/final round default, and embedded media bytes.
- `UnknownQuestionTypeAndParameters_AreUntouchedUntilKnownBehaviorIsExplicitlySelected`
  proves display and ordinary save do not normalize future values.
- `SecretBehaviorSwitchAndEndpointEdits_PreserveCompatibleSettingsAndUndoAsSingleChanges`
  proves compatible Secret-family settings survive explicit switches and that
  the derived endpoint step participates in the same undoable edit.
- `Inspector_QuestionBehaviorControlsCreateCanonicalSecretTimingAndPostAnswerParameters`
  drives the compiled Avalonia controls and verifies canonical values,
  contextual visibility, command routing, localization, and accessible names.
- The native Linux v0.2.0 receipt opens a real Unicode/space-path fixture in the
  packaged tar application, selects Secret, authors theme and fixed price 700,
  adds post-answer text, saves, closes, reopens, and closes cleanly. Programmatic
  `content.xml` inspection and the safe-save log confirm the canonical result.

The release test total is 350 passed, 0 failed, 0 skipped. Exact artifact and
native-smoke evidence is recorded in `PORT_STATUS.md` and
