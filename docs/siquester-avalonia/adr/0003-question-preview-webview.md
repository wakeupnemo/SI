# ADR 0003: Question preview WebView

Status: Accepted; native Linux text-player slice verified, package-media routing pending

Reuse `QuestionPlayViewModel`, `IWebInterop`, the existing `wwwroot` assets, and JSON protocol behind `IQuestionPreviewService`. Keep protocol records and capability descriptors in the platform-neutral view-model assembly; native controls and lifecycle belong to the frontend/desktop host.

Use the official `Avalonia.Controls.WebView` 12.1.0 package. It is publicly distributed under MIT from `AvaloniaUI/Avalonia.Controls.WebView`; the reviewed package source commit is `b45e042d21d96371bb6d07822a55c85ee5f74d2f`, and the reviewed NuGet package SHA-256 is `1249cd4016595e1168a7e0562be1330f117592ba0928fa9bf38d1172b8e76491`. It uses WebView2 on Windows, WKWebView on macOS, and WPE WebKit or GTK 3/WebKitGTK on Linux. No XPF, Accelerate entitlement, paid media component, or proprietary build tool is required.

The implemented host probes native engines only when preview is requested. It serves a bounded allowlist of application-owned player assets from an ephemeral loopback port under a random 128-bit route, with no-store, CSP, frame denial, MIME hardening, and no query/traversal aliases. Navigation is restricted to that exact origin and randomized path; popups are always handled and denied. The compatibility bridge leaves the original WPF WebView2 API untouched, adapts Avalonia engines through `invokeCSharpAction`, emits an explicit readiness message, and passes outbound JSON as encoded data rather than executable source. Inbound JSON must be a bounded object before it reaches the retained interop seam. Native events, cancellation, and the WebView control are detached when the preview leaves the visual tree.

`QuestionPreviewHostDescriptor` exposes only local-file or loopback HTTP(S) sources and represents missing backend/assets without a URI. Missing Linux WebKit, Windows WebView2, unsupported platforms, missing assets, loading, and runtime failure are distinct localized non-fatal states; ordinary editing and startup continue. WPF retains its existing application-owned file source and does not depend on Avalonia.

The native Linux receipt renders and advances the retained player through WebKitGTK 2.52.6 using the semantic round-trip SIQ fixture. Remaining parity requires controlled package-media URI registration, replay and answer-option runtime receipts, repeated open/close process and memory measurements, and native macOS/Windows execution. Package-provided HTML remains excluded from this application-owned origin until its separate restrictive policy is implemented.
